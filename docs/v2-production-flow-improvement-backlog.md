# V2 생산 진행방식 개선 백로그

상태: 보류

이 문서는 발주 품목별 생산 진행방식, 검수 직행, 철형 및 관련 원가 처리를 즉시 구현하지 않고 추후 작은 단위로 개선하기 위한 백로그다.

## 현재 문제

- 외주작업지시 대상 여부가 실제 발주 또는 LOT의 실행방식이 아니라 품목 라우팅 템플릿 이름에 의존한다.
- 알 수 없는 라우팅 템플릿명은 기본 외주공정으로 취급될 수 있다.
- 검수 직행은 `검수만진행` 라우팅 템플릿명에 의존한다.
- 철형은 재활용 원단을 사용하므로 원단원가는 반영하지 않아야 하지만, 외주가공비와 검수 이력은 관리해야 한다.
- 외주작업지시 없이 진행하는 LOT을 명시적으로 구분할 발주·LOT 속성이 없다.

## 목표 업무 흐름

| 생산 진행방식 | 외주작업지시 | 원단원가 | 외주가공비 | 검수 연결 |
|---|---:|---:|---:|---|
| 기본 외주공정 | 필요 | 반영 | 기존 정책 | 외주 출고 후 |
| 검수 바로 진행 | 없음 | 없음 | 없음 | 즉시 검수 대상 |
| 철형(재활용 원단) | 철형 전용 | 반영하지 않음 | 도무송 가공비만 | 철형 출고 후 |

## 선행 업무 규칙 확인

- [ ] 발주서 전체가 아니라 발주 품목 라인별로 진행방식을 선택하는 규칙 확정
- [ ] 일반 라우팅 품목도 사용자가 `검수 바로 진행`으로 변경할 수 있는지 확정
- [ ] 철형 작업이 항상 외주공정인지 확정
- [ ] 철형 외주가공비가 `DIECUT` 한 종류에만 포함되는지 확정
- [ ] 철형에서 원단 LOT, 사용량 및 원단 재고이동을 완전히 생성하지 않는지 확정
- [ ] 재작업 LOT이 부모 LOT 진행방식을 상속할지, 생성 시 별도 선택할지 확정
- [ ] 진행방식 변경을 허용할 마지막 업무 시점과 변경 승인 권한 확정

## 개선 작업 목록

### PF-01. 기존 데이터 및 문자열 분기 감사

상태: 대기

- 라우팅 템플릿명별 LOT, 외주작업지시 및 검수일정 수를 확인한다.
- `검수만진행`, `무지`, `인쇄` 외 이름이 기본 `CUT`으로 처리된 사례를 확인한다.
- 기존 철형 업무가 어떤 코드와 메모로 기록됐는지 확인한다.
- 운영 데이터는 변경하지 않고 감사 결과만 남긴다.

### PF-02. 생산 진행방식 코드 정의

상태: 대기

- `STANDARD_OUTSOURCE`: 기본 외주공정
- `DIRECT_INSPECTION`: 검수 바로 진행
- `RECYCLED_DIECUT`: 철형(재활용 원단)
- 자유입력 문자열로 업무 분기를 만들지 않는다.
- 허용 코드는 API와 DB 제약조건 양쪽에서 검증한다.

### PF-03. 발주 품목 라인 저장 필드 추가

상태: 대기

- `order_line.production_flow_type`을 필수로 저장한다.
- 예외 사유나 작업 참고사항을 위한 `production_flow_memo`를 검토한다.
- 기존 데이터는 라우팅 템플릿 기준으로 안전하게 백필한다.
- 마이그레이션 전에 데이터 분포와 롤백 방법을 확인한다.

### PF-04. 발주 등록 및 엑셀 등록 UI

상태: 대기

- 발주 품목별 `생산 진행방식` 선택 열을 추가한다.
- 품목 라우팅이 `검수만진행`이면 검수 직행을 기본 추천한다.
- 나머지 품목은 기본 외주공정을 추천한다.
- 철형 선택 시 `원단원가 제외, 도무송 외주가공비만 반영` 안내를 표시한다.
- 엑셀 입력값은 허용된 표시명 또는 코드만 받아 검증한다.

### PF-05. LOT 진행방식 스냅샷

상태: 대기

- LOT 생성 시 발주 품목의 확정 진행방식을 LOT에 복사한다.
- 이후 품목 라우팅이나 발주 정보가 바뀌어도 기존 LOT 경로가 변하지 않게 한다.
- 재작업 LOT의 상속·변경 규칙과 변경 사유 저장을 포함한다.

### PF-06. 생산 진행방식 중앙 정책 서비스

상태: 대기

- 외주작업지시 대상 여부를 한 곳에서 결정한다.
- 원자재 배정 필요 여부를 한 곳에서 결정한다.
- 검수 직행 및 외주 출고 확인 필요 여부를 한 곳에서 결정한다.
- 적용 가능한 가공비 분류를 한 곳에서 결정한다.
- 화면·쿼리·서비스에 개별 문자열 조건을 반복하지 않는다.

### PF-07. 외주작업지시 후보 조회 개선

상태: 대기

- 기본 외주공정 LOT만 기존 외주작업지시 후보에 표시한다.
- 검수 직행 LOT은 외주 후보에서 제외한다.
- 철형 LOT은 철형 전용 후보로 구분한다.
- 취소 및 재등록 이력과 기존 활성 중복 방지 규칙을 유지한다.

### PF-08. 검수 직행 처리

상태: 대기

- `DIRECT_INSPECTION` LOT을 외주작업지시 없이 검수작업지시 대상으로 제공한다.
- 검수 접수 시 외주 출고 완료 조건을 적용하지 않는다.
- 기존 `검수만진행` 템플릿명 분기는 호환 기간 후 제거한다.
- LOT·수주 상태와 생산진행현황 스냅샷을 함께 검증한다.

### PF-09. 철형 외주작업지시

상태: 대기

- 철형을 기존 `CUT` 또는 `PRINT`와 구분되는 운영 흐름으로 관리한다.
- 작업 업체, 작업수량, 예상 생산수량, 입고·작업완료·출고 이력을 저장한다.
- 원단 LOT 배정 UI와 원자재 소모 이동은 생성하지 않는다.
- 철형 출고 완료 후에만 검수 접수할 수 있게 한다.

### PF-10. 철형 원가 정책

상태: 대기

- 철형 작업에 원자재 배정 및 원단원가 스냅샷을 만들지 않는다.
- 원단원가는 0원으로 취급한다.
- 철형 외주작업그룹은 도무송 가공비 대상에만 포함한다.
- 재단 가공비 대상에 철형 작업이 중복 노출되지 않게 한다.
- 향후 제품원가 계산에서도 외주가공비만 반영되는지 검증한다.

### PF-11. 변경 제한 및 감사 이력

상태: 대기

- 외주작업지시 또는 검수일정 생성 전까지만 진행방식을 변경할 수 있게 한다.
- 변경 사유를 필수로 저장한다.
- 연결 업무가 생긴 이후에는 변경을 차단하고 취소·재처리 절차를 안내한다.
- 변경자와 변경 시각을 추적한다.

### PF-12. 조회 화면과 타임라인 표시

상태: 대기

- 발주 목록·수주상세·LOT 목록·LOT 상세에 진행방식 배지를 표시한다.
- 철형 작업지시와 검수 연결을 LOT 타임라인에 표시한다.
- 검수 직행 LOT은 외주단계가 없는 정상 흐름으로 표현한다.

### PF-13. 자동 및 수동 검증

상태: 대기

- 기본 외주공정 E2E 테스트
- 검수 직행 E2E 테스트
- 철형 외주 → 출고 → 검수 E2E 테스트
- 철형 원단 재고 미차감 및 원단원가 미반영 테스트
- 철형 도무송 가공비 단독 반영 테스트
- 재작업 LOT 상속·변경 테스트
- 취소·재등록 및 중복 방지 회귀 테스트
- 기존 무지·인쇄·분할검수·LOT 완료·수주 완료 회귀 테스트

## 권장 진행 순서

1. PF-01 업무·데이터 감사
2. 선행 업무 규칙 확정
3. PF-02~PF-06 공통 기반
4. PF-08 검수 직행
5. PF-09~PF-10 철형
6. PF-07 후보 조회 최종 전환
7. PF-11~PF-12 운영 화면과 감사
8. PF-13 전체 검증

각 작업은 별도 분석, 구현, 자동 검증, 수동 확인 순서로 완료하고 다음 작업으로 진행한다.

## 이번 범위에서 하지 않는 작업

- 사용자가 공정 순서를 자유롭게 조합하는 범용 워크플로 엔진
- 기존 라우팅 템플릿 전면 재설계
- 운영 데이터의 즉시 일괄 변경
- 철형 원단을 가상의 유상 원자재 재고로 등록하는 처리
