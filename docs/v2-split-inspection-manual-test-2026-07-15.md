# V2 분할검수 완료 수동 테스트 메모

테스트 예정일: 2026-07-15

## 목적

2026-07-14에 분할검수 실적을 등록한 LOT의 후속 검수를 최종 완료하고, 회차별 실적·불량·메모와 LOT 및 수주 상태가 일관되게 반영되는지 확인한다.

## 진행 방식

- `[ ]`: 미확인 또는 이상이 있어 남겨둘 항목
- `[x]`: 사용자가 직접 확인하여 정상으로 소거한 항목
- 해당되지 않는 항목은 체크하지 않고 `해당 없음`과 사유를 적는다.
- Codex가 한 항목씩 안내하고, 사용자가 알려준 결과를 이 문서에 반영한다.
- 이상이 발견되면 해당 항목은 `[ ]`로 유지하고 바로 아래에 실제 결과, 오류 문구 및 캡처 경로를 기록한다.
- 테스트 종료 시 `[ ]`로 남은 항목만 수정 후보로 모아 원인을 분석한다.

## 사전 준비 체크리스트

- [ ] 최신 코드로 WPF 프로그램을 완전히 종료한 뒤 다시 빌드·실행한다.
- [ ] 운영 데이터가 아닌 테스트 가능한 LOT를 사용한다.
- [ ] 2026-07-14에 등록한 1차 분할검수의 LOT 번호를 기록한다.
- [ ] 1차 분할검수에 입력한 다음 검수일이 2026-07-15인지 확인한다.
- [ ] 1차 분할검수의 분할사유, 검수실적 메모, 불량내역 및 첨부이미지를 미리 기록하거나 캡처한다.

테스트 대상 기록:

- LOT 번호:
- 수주번호:
- 1차 검수일:
- 1차 검수수량:
- 1차 분할사유:
- 1차 검수실적 메모:
- 1차 불량수량 및 불량유형:

## 테스트 순서

### 1. 1차 분할검수 실적 확인

- [ ] `검수관리 → 검수실적관리`에서 대상 LOT를 검색한다.
- [ ] 1차 실적이 `분할`, `1차`로 표시되는지 확인한다.
- [ ] 상세보기에서 검수수량, 양품수량, 불량수량, 분할사유, 검수실적 메모, 불량 메모 및 이미지를 확인한다.
- [ ] 현재 규칙상 `PARTIAL_DONE` 분할실적에는 수정 버튼이 표시되지 않는지 확인한다. 이 동작의 변경 여부는 전체 테스트 후 결정한다.

### 2. 후속 검수 일정 확인 및 시작

- [ ] `검수관리 → 검수일정관리`에서 대상 LOT의 2026-07-15 후속 일정을 찾는다.
- [ ] 후속 일정이 중복 없이 1건만 생성되어 있는지 확인한다.
- [ ] 일정 상태가 `접수`이면 검수를 시작한다. `대기`이면 기존 정상 절차에 따라 접수 후 시작한다.
- [ ] 동일한 LOT에 당일 중복 검수가 생성되거나 차단 규칙이 비정상적으로 작동하지 않는지 확인한다.

### 3. 2차 최종 검수실적 등록

- [ ] 분할검수 선택을 해제한 최종검수로 등록한다.
- [ ] 남은 수량을 기준으로 2차 검수수량, 양품수량 및 불량수량을 입력한다.
- [ ] 회차 구분 확인을 위해 1차와 다른 불량유형 또는 불량 메모를 입력한다.
- [ ] 가능하면 2차 불량이미지도 첨부한다.
- [ ] 검수실적 등록의 `메모`에 `2차 최종검수 테스트 메모`처럼 회차를 구분할 수 있는 내용을 입력한다.
- [ ] 화면에 표시되는 누적 판매가능수량과 출고·재고편입·폐기 배분 합계가 일치하는지 확인하고 저장한다.

2차 입력 기록:

- 2차 검수수량:
- 2차 양품수량:
- 2차 불량수량 및 불량유형:
- 2차 검수실적 메모:
- 출고수량:
- 재고편입수량:
- 폐기수량:

### 4. 저장 직후 상태 확인

- [ ] 저장 성공 후 수정창이 닫히는지 확인한다.
- [ ] 상세보기 화면이 자동으로 새로고침되는지 확인한다.
- [ ] 검수실적관리 목록에 1차 분할실적과 2차 최종실적이 모두 표시되는지 확인한다.
- [ ] 2차 최종실적 상세보기의 수량, 메모, 불량내역 및 이미지가 저장값과 일치하는지 확인한다.

### 5. LOT 상세 확인

- [ ] `LOT 관리`에서 대상 LOT 상세를 연다.
- [ ] LOT 상태가 `완료(DONE)`로 변경되었는지 확인한다.
- [ ] 진행 타임라인에 1차 분할검수와 2차 최종검수가 시간순으로 표시되는지 확인한다.
- [ ] `검수 회차` 표에서 1차와 2차 수량이 각각 정확한지 확인한다.
- [ ] `검수 회차` 표의 마지막 `분할사유` 열에는 1차 분할사유만 표시되고 2차에는 `-`가 표시되는지 확인한다.
- [ ] `검수회차별 불량 및 첨부이미지`에서 불량내역이 1차와 2차로 구분되고 각 이미지가 올바르게 열리는지 확인한다.
- [ ] 불량 메모가 해당 불량 행에 표시되는지 확인한다.
- [ ] `검수실적 회차별 특이사항`에서 1차와 2차의 검수실적 등록 메모가 각각 표시되는지 확인한다.
- [ ] 검수실적 메모 영역에 분할사유가 섞여 표시되지 않는지 확인한다.

### 6. 수주 상태 및 회귀 확인

- [ ] 해당 수주의 모든 비취소 LOT가 완료된 조건이라면 수주 품목 상태도 완료되는지 확인한다.
- [ ] `영업관리 → 발주리스트 → 수주상세` 진행 타임라인에서 대상 LOT의 진행 흐름이 정상인지 확인한다.
- [ ] 대상 수주에 재작업 LOT가 있다면 재작업 생성 이벤트에 재작업 원인 메모가 계속 표시되는지 확인한다.

## 최종 판정 체크리스트

- [ ] 후속 검수 일정은 한 건만 존재한다.
- [ ] 최종 검수 저장 후 LOT 상태가 `DONE`이 된다.
- [ ] 모든 LOT가 완료된 수주 품목은 완료 상태가 된다.
- [ ] 1차와 2차 검수실적, 불량내역, 이미지 및 메모가 회차별로 섞이지 않는다.
- [ ] 분할사유는 검수 회차 표에, 검수실적 등록 메모는 별도 특이사항 표에 표시된다.
- [ ] 상세 수정 저장 후 상세보기와 목록이 최신 데이터로 갱신된다.

## 현재 알려진 제한사항

- 분할검수 실적의 일정 상태는 `PARTIAL_DONE`이며, 현재 상세보기에서는 수정 버튼이 표시되지 않는다.
- 백엔드도 `PARTIAL_DONE` 일정의 실적 저장을 허용하지 않는다.
- 분할검수 실적 수정 지원 여부와 안전한 수정 범위는 이번 완료 흐름 테스트 결과를 본 뒤 별도로 결정한다.
